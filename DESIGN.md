# Design: skilld

> Generated by `nuxt-frontend-design`. Source of truth for visual tokens. Compatible with `@google/design.md`.
>
> **Front matter** holds the machine-readable tokens. **Prose below** holds rationale and judgment rules. The full visual system lives in [`.claude/context/design-guidelines.md`](.claude/context/design-guidelines.md); voice and copy rules live in [`.claude/context/brand-guidelines.md`](.claude/context/brand-guidelines.md). Token refs use `{path.to.token}`.

## Aesthetic Direction

- **Theme**: quiet editorial (warm surfaces, border-driven, compact monospace chrome)
- **Mode**: both (dark-first preference, light fully supported)
- **Vibe**: restrained technical curation
- **Influences**: npmx.dev (compact mono UI, OKLCH neutrals), Are.na (institutional minimalism), Wirecutter (editorial trust), Letterboxd (people-first discovery)
- **Design principle**: We prioritise restraint and editorial clarity over visual impact. The interface recedes; the curation speaks.
- **Personality of motion**: crisp and quiet. 200ms ease-out, 4px translateY rises, 60ms stagger. Total motion budget under 400ms. No bounce, no elastic, no slow drama.

## Color Decisions

| Role | Value | Why |
|------|-------|-----|
| Primary | rose (`{colors.primary}`) | warm coral signals people and curation; used as ≤10% accent only |
| Neutral | stone (`{colors.neutral}`) | warm grays at OKLCH chroma 0.005–0.014, hue 60, never pure gray |
| Surface light | `#fafaf9` | warm bg-default, oklch(0.98 0.005 60) |
| Surface dark | `#1c1917` | warm bg-default, oklch(0.14 0.008 60), never pure black |
| Extended | none | semantic colors (success/warning/error) added when first needed |

- **Neutral tinting**: every neutral is OKLCH at hue 60, chroma 0.005–0.014. Pure 0-chroma grays are banned.
- **Color budget**: 90% warm stone, 10% rose. The accent is rare so it stays meaningful. Solid rose appears on primary CTAs, active nav, and featured-content badges only.
- **Primary darkening**: `--color-rose-500` is overridden to `oklch(0.555 0.225 17.32)` so white-on-primary buttons clear WCAG AA.

### Contrast & Accessibility

- **Body text contrast**: `oklch(0.93)` on `oklch(0.14)` ≈ 11:1 in dark mode, exceeds AAA. Light mode `oklch(0.18)` on `oklch(0.98)` ≈ 14:1.
- **Muted text**: `--ui-text-muted` at `oklch(0.62)` (dark) / `oklch(0.45)` (light) holds 4.5:1 against the matching bg-default.
- **High contrast**: `@media (prefers-contrast: more)` strengthens text and borders; tested for both modes.
- **Known risks**: rose on warm-stone surface in small badges; verify per usage. Solid rose buttons are pre-cleared via the darkened primary token.

## Typography

| Role | Font | Why |
|------|------|-----|
| Body (`--font-sans`) | Plus Jakarta Sans | warm geometric sans, editorial body voice |
| Mono (`--font-mono`) | IBM Plex Mono | UI chrome (buttons, inputs, nav, badges, metadata); the single biggest contributor to the quiet feel |
| Display | Plus Jakarta Sans 600, larger sizes | mono handles display duties at smaller scales; Jakarta only at hero/page-heading scale |

- **Type system**: fixed rem scale. UI chrome stays at `text-xs` to `text-sm`; body at `text-sm` to `text-base`; large type reserved for page headings.
- **OpenType features**: `tabular-nums` on every numeric display (install counts, collection sizes, version strings).
- **Heading pattern**: section labels use the `.section-label` utility (mono, `text-xs`, uppercase, widest tracking, muted color).
- **Mono rule**: if it's chrome (action, label, metadata, navigation), it's mono. If it's content, it's sans.

## Icons

- **Collection**: lucide
- **Why**: 2px strokes pair with the compact mono chrome and avoid decorative weight
- **Size**: `size-4` (16px) default, `size-3.5` (14px) inline with small text
- **Color rule**: monochrome via `text-current`. Colour only for semantic states (success/error/warning) and primary on active or selected states.

## Component Rules

> Behavioral constraints that tokens alone don't communicate. Surfaces live in YAML front matter; this section holds the always/never rules.

- **Radius**: `rounded-lg` (`{rounded.md}`, 8px) globally. `rounded-full` only for avatars. `rounded-xl` is banned: too soft for the quiet system.
- **Buttons**: solid primary for main CTAs; outline neutral for secondary; ghost for inline actions. Every button uses `font-mono`. Solid variant is the default (`button.defaultVariants.variant: 'solid'`).
- **Cards**: 1px border + warm surface. Hover transitions on border-color only. No glow, no shadow, no nested cards (use spacing + dividers for inner hierarchy).
- **Avatars**: `rounded-full`, stack with `-space-x-2`, `border-2 border-[var(--ui-bg)]` for separation in groups.
- **Badges**: `subtle` variant, size `xs`, mono font, by default. Use for stack labels and agent compatibility.
- **Inputs**: `outline` variant, mono font, `px-3 py-2`. No bottom-border-only or pill shapes.
- **Tooltips**: use `UiTooltip` (built on `UPopover` hover mode) for any tooltip with title + description. `UTooltip` is reserved for single-line hints on icon buttons.
- **Focus rings**: Nuxt UI default rings on form controls; 2px primary outline + 2px offset on everything else (set in `main.css`).
- **PDS terminology**: always "PDS", never spelled out in UI. Pair with a `UiTooltip` or `<abbr>` so first-time users can learn it. Storage destination never appears in a button label.

## Spatial & Motion

- **Spacing system**: 4pt base. 4, 8, 12, 16, 24, 32, 48px.
- **Spacing philosophy**: compact and structural. Sections separate with `py-12 md:py-16` (not `py-16 md:py-24`). Cards at `p-4`. Whitespace is structure, never decoration.
- **Vertical rhythm**: `gap-3` to `gap-4` between list items; `gap-6` to `gap-8` between sections within a page.
- **Container width**: `max-w-5xl` with `px-4 sm:px-6`. Wider feels institutional in the wrong way.
- **Transition speed**: 200ms for every micro-interaction (hover, focus, expand/collapse).
- **Animation style**: fade + `translateY(4px)` rise, 60ms stagger between siblings via `motion-v`. Total under 400ms.
- **Reduced motion**: `prefers-reduced-motion: reduce` collapses to opacity-only crossfades; the noise field freezes at ambient shimmer state.

## Responsive Strategy

- **Approach**: mobile-first, three breakpoints (`sm`/`md`/`lg`).
- **Input method**: hover effects gated behind `@media (hover: hover)`; touch targets ≥ 44px.
- **Navigation**: mobile hamburger with slide drawer; desktop horizontal nav.
- **Progressive disclosure on touch**: every hover-revealed datum gets a tap-to-expand path on touch devices. No hover-only data ever.

## Voice & Tone

> Full voice system, banned vocabulary, and messaging framework live in [`.claude/context/brand-guidelines.md`](.claude/context/brand-guidelines.md). UI-specific patterns:

- **Button labels**: short verb phrases in mono ("Browse", "Install", "View skills"). Never include "PDS" or storage destination in button text.
- **CTA pattern**: first action `Publish [noun]`; updates `Update [noun]`. Action + object, never the destination.
- **Error style**: direct, helpful, no theater. "Couldn't load curators. Check your connection and try again."
- **Empty states**: acknowledge → explain value → provide action. "No collections yet. Curators bundle their favorite skills into collections you can install with one command."
- **Data labels**: every metric is labeled and contextual. "12 skills" not "12". "Updated 3d ago" not "Mar 25".

## Avoid

> Things that break the aesthetic. Check this list before adding new patterns.

- Glow, drop-shadows on cards, backdrop-blur on surfaces (the brand noise field has a controlled additive bloom; that is the only exception).
- Cold accents (blue, cyan, purple) as primary or feature colors.
- Pure black (`#000`) or pure 0-chroma gray anywhere.
- Dense data tables on first-level views; density grows with depth.
- Emoji or playful illustrations.
- Gradient text effects.
- Cards nested in cards.
- `rounded-xl` on components.
- Large font sizes in UI chrome; reserve large type for page headings.
- Generous "breathing room" padding; padding is structural.
- Showing all data at once; layer through progressive disclosure (hover, expand, detail panel).
- Spelling out "Personal Data Server" in UI; always "PDS" + tooltip.
- Mentioning storage destination in button labels.

## Brand Noise Field

## Design Decisions

> Append-only log of intentional choices the user has confirmed. Do not re-litigate; only add.

- **Color budget 90/10, not 60-30-10**: rose is rare so it stays meaningful. Confirmed when tightening from earlier 60-30-10 split.
- **Mono-first chrome**: every interactive element uses IBM Plex Mono. This is the single largest contributor to the quiet feel; do not "soften" by switching to sans for buttons.
- **`rounded-lg` (8px) global**: not `rounded-md` (too tight for cards), not `rounded-xl` (too soft). One radius for everything except `rounded-full` avatars.
- **Compact spacing**: `py-12 md:py-16` for sections, `p-4` for cards. Resist requests to "add breathing room" with `py-24`; that breaks the editorial density.
- **Solid primary buttons only**: ghost or outline for primary CTAs is banned because they vanish on warm surfaces. Solid is the default in `app.config.ts`.
- **Darkened rose-500 token**: `oklch(0.555 0.225 17.32)` overrides Tailwind's default so white-on-primary clears AA. Do not revert; do not introduce a second rose.
- **No pure black**: dark mode bg starts at `oklch(0.14 0.008 60)`. If a surface looks too light, deepen via OKLCH chroma+hue, not by going to `#000`.
- **PDS abbreviation rule**: never spell out "Personal Data Server" in UI copy; always pair "PDS" with a tooltip on first introduction in a view.
