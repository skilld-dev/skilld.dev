Ferncastle — Book Reservation Flow

Fictional library app · architecture view · numbered path shows a patron placing a hold

Reservation steps

  1. Patron taps ReservePhone App → API Gateway · POST /holds {bookId}
  2. Token checkedGateway → Auth Service · reject with 401 if invalid
  3. Request routedGateway → Catalog Service with patron id
  4. Title resolvedCatalog → Search Index · confirm edition & branch copies
  5. Hold writtenCatalog → Postgres · lock copy row, insert hold, assign queue position
  6. Event publishedCatalog → Holds Queue · HoldPlaced (async)
  7. Patron gets answerCatalog → Gateway → App · 202 Accepted + queue position
  8. Notifier consumesHolds Queue → Push Notifier
  9. Confirmation pushedPush Notifier → Phone App · later also “ready for pickup”
