[sync-github-skills] failures

That is the credential, not the repositories. `getRepoSummary` gets HTTP 401 from the GitHub GraphQL API, `syncRepo` maps it to a per-repo `failed`, and because 401 is neither 404 nor 410 the repo is never marked, so `repo_meta_synced_at` never advances and the same set fails again the next hour.

### 2. The front-door 522 is a Worker self-fetch, not an outage (regressed from "flap", now fixed in tree)

The retry shipped in `76d94b3` (3 attempts, 1.5s apart) and the 2026-07-25 health run still recorded 522 on all three of `/`, `/skills`, `/guides`, identical to 2026-07-24, while external probes returned 200 in both windows and Workers analytics recorded zero non-OK outcomes across 37,404 requests.

Cause: `loadFrontDoor` called `fetch('https://skilld.dev/')`{lang="ts"} from inside the Worker that serves skilld.dev. The request leaves the runtime, fails to route back, and returns 522 every time. Retrying a deterministic condition changes nothing.

Fixed by adding a `SELF` service binding and probing through it, so the request dispatches straight to this Worker's fetch handler. A missing binding now rejects rather than falling back to the public URL, which keeps the RED gate honest.

The prior expiry was `ai-generate-submit` on 2026-07-23T14:15Z, outside this window. Backdrop is the chronic `ai-ready:cron` rate limiting. Watch, do not chase yet.

## Resolution (same day)

**The token rotation fixed half of it.** The 06:01Z run went from `failed=10` to `failed=5`, and 5 repos synced for the first time in days. The remaining 5 were exactly the renamed ones, which looked like strong evidence that renames were the cause. That inference was wrong.

Worker logs from the 07:00Z and 08:00Z runs gave the real reasons:

```
steipete/clawdis                          commit_batch_failed:502
affaan-m/everything-claude-code           blob_batch_failed:502
composiohq/awesome-claude-skills          blob_batch_failed:502
jeremylongshore/claude-code-plugins-plus  blob_batch_failed:504 / Unexpected end of JSON input
```

`getBlobsBatch` built one GraphQL alias per file with no chunking. `affaan-m/everything-claude-code` has 890 SKILL.md files, producing a 61 KB query that GitHub answers with an nginx 502 after 10.8s. Direct measurement against that repo: 890 aliases 502s, 50 per request returns 200 across 18 requests. The renamed repos correlated only because they are the largest. The 502 body is HTML, which is where `Unexpected end of JSON input` came from: the client called `res.json()`{lang="ts"} on an nginx error page.

Shipped the same day:

| Commit | Change |
| --- | --- |
| `428b275` | Chunk batched GraphQL at 50; a failed chunk returns the upstream status rather than a partial map, which would read as "the repo lost files" and delete skills the sync failed to read |
| `e39fd32` | Report every reason red-first instead of only the winning tier; errored sync jobs carry their error text into the reason |
| `a03d75d` | Read `github-authentication-token-expiration` and alert: expired is RED, inside 14 days is AMBER. Current token expires 2026-10-23 |

**Why two days passed unnoticed.** The health check did gate on errored sync jobs, but `evaluateDailyHealthStatus` returned only the winning severity's reasons. The phantom 522 produced a RED, which discarded every amber beneath it. The operator email named the one thing that was not broken and omitted the outage.

Also resolved: `recompute-skill-scores (missing_run)`{lang="ts"} was a bootstrap artefact of migration `0074`, with two consecutive successes since. The `Test` workflow is green across all three jobs.

Still open: renamed repos keep their old identity. Nothing breaks today, because GraphQL resolves old names and the old pages are `noindex,follow`, but `steipete/summarize` and `steipete/weather` are `seo_indexable=1` and would 404 if sync ever adopted the new owner.
