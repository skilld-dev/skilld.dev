- Evidence: `Error: e58.split is not a function`, culprit `GET /__nuxt_island/OgImageCuratorTakumi_…json?props={"handle":2114632142,"collectionCount":0,"skillCount":0}`. First seen `2026-08-11T23:17:36Z`, last seen `2026-08-12T01:32:13Z`, 2 events, 1 user. Permalink: https://harlan-zw.sentry.io/issues/7666848478/
- `SKILLD-V` is the same failure surfaced one layer out, as the `/_og/d/…Curator.takumi,handle_2114632142….png` fetch returning the island error. Permalink: https://harlan-zw.sentry.io/issues/7666848469/
- Hypothesis: confirmed by reading the deployed source. `app/components/OgImage/Curator.takumi.vue` at `d2616c5` declares `handle: string` and calls `getInitials(displayName || handle)`{lang="ts"}, which calls `.split(' ')`{lang="ts"}. A GitHub login made only of digits deserializes from the island query string as a `number`, so `.split` does not exist. The prop type is a claim about the wire format that the wire format does not honour.
- A fix already exists in the working tree (uncommitted): `Curator.takumi.vue` now types the props as `string | number | null` and coerces through new `app/utils/og-props.ts` helpers. It is not committed and not deployed.
