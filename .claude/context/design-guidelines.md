# Design Guidelines — skilld.dev

> Generated by `nuxt-frontend-design-system`. This file captures the *intent* behind design decisions so future work stays cohesive across conversations, contributors, and skills.

## Design Principles

### 1. Quiet

**"Confidence is quiet. The interface recedes; the content speaks."**

Quiet means restraint at every level: fewer colors, smaller type in chrome, compact containers, solid defined edges. Character and polish come from precision, not volume. A quiet interface earns trust by never shouting.

Practically:
- One accent color used sparingly (10% of surface area, max)
- UI chrome in monospace at small sizes; content in the sans-serif
- Borders, not shadows, define boundaries
- No glow, no gradient, no blur, no decorative flourish
- Compact components: tight padding, defined shapes, minimal radius
- Whitespace is intentional structure, not generous filler

### 2. Progressive Data Discovery

**"Show the signal. Let curiosity reveal the detail."**

We have data on everything. Giving it all at once overwhelms. Top-level views present simplified, scannable summaries. Complexity lives one interaction away: hovers, collapsibles, expandable rows, detail panels.

Practically:
- First-level: one key metric or label per item (e.g. "12 skills" not a full breakdown)
- Hover: secondary data appears in tooltips or inline expansions (version, last updated, source)
- Click/expand: full detail view with all metadata, changelogs, compatibility matrices
- Never hide critical decision data; hide supplementary context
- Data density increases as the user drills in, never on the landing surface
- Collapsible sections default closed for reference data (API changes, type signatures)

### 3. Human Warmth

**"Warm enough to feel curated by a person."**

Every surface has warm undertone. The accent is coral/rose. The voice is editorial, not corporate. But warmth is the undertone, not the headline; it lives in the color temperature and the copy, not in decoration.

## Aesthetic Direction

- **Theme**: quiet editorial (warm surfaces, border-driven, compact)
- **Mode**: both (dark-first, light mode supported)
- **Vibe**: restrained technical curation
- **Influences**: npmx.dev (compact monospace UI, border hierarchy, OKLCH system), Are.na (institutional minimalism), Wirecutter (editorial trust), Letterboxd (people-first discovery)

## Color Decisions

| Role | Value | Why |
|------|-------|-----|
| Primary | rose | warm coral signals people and curation, used sparingly as accent only |
| Neutral | stone | warm grays tinted at OKLCH hue 60 for subconscious warmth |
| Extended | none yet | semantic colors (success, warning, error) when needed |

- **Neutral tinting**: all backgrounds and surfaces use OKLCH with chroma 0.005-0.014 at hue 60. Never pure gray, never pure black
- **Color budget**: 90% warm stone neutrals (surfaces, text, borders), 10% rose accent (CTAs, active states, badges for featured content). The previous 60-30-10 split gave rose too much presence; quiet means the accent is rare and therefore meaningful

### Contrast & Accessibility

- **Body text contrast**: oklch(0.93) on oklch(0.14) in dark mode provides 11:1+ ratio, exceeds AAA
- **Dark mode adjustments**: backgrounds start at oklch(0.14) not pure black, accent stays vibrant, muted text at oklch(0.62) maintains 4.5:1 against dark bg
- **Known risks**: rose on warm stone surfaces needs contrast verification for small text badges
- **High contrast mode**: prepared for but not yet implemented; borders and text should pass without adjustment

## Typography

| Role | Font | Why |
|------|------|-----|
| Body (`--font-sans`) | Plus Jakarta Sans | warm geometric sans-serif for content text, editorial feel |
| UI chrome (`--font-mono`) | IBM Plex Mono | monospace for buttons, inputs, nav, labels, metadata; creates technical restraint |
| Display | not used | mono handles display duties at larger sizes |

- **Size philosophy**: small by default in UI chrome. Monospace elements use text-xs to text-sm. Content body uses text-sm to text-base. Display headings are the only place text goes large
- **OpenType features**: tabular-nums on any numeric displays (install counts, collection sizes)
- **Heading pattern**: section labels use `.section-label` (mono, xs, uppercase, tracking-widest, muted)
- **Monospace in UI**: buttons, inputs, links, navigation items, badges, and metadata all render in mono. This is the single biggest contributor to the quiet feel

## Icons

- **Collection**: lucide
- **Why**: clean 2px strokes pair well with compact monospace UI; minimal and editorial
- **Size**: 16px (size-4) default, 14px for inline with small text
- **Color rule**: monochrome inheriting text-current; color only for semantic states (success, error, warning) and primary accent on active/selected states

## Component Rules

### Sizing & Shape
- **Global radius**: rounded-lg (8px). Not rounded-xl (too soft), not rounded-md (too tight for cards)
- **Button padding**: px-3 py-1.5 (sm), px-4 py-2 (md). Compact, defined
- **Card padding**: p-4 default, p-5 for detail views. Not p-6 (too generous)
- **Input padding**: px-3 py-2 with monospace font

### Variants
- Buttons: solid primary for main CTAs; outline neutral for secondary; ghost for inline actions. All buttons use mono font
- Cards: rounded-lg with 1px border, warm surface. Hover transitions on border-color only, no glow, no shadow
- Avatars: rounded-full, stacked with -space-x-2 for curator groups, border-2 border-[var(--ui-bg)]
- Badges: subtle variant, size xs, mono font. Used for stack labels and agent compatibility. xs keeps badges subordinate to content
- Focus rings: Nuxt UI default ring behavior

### UiTooltip
Use `UiTooltip` (not `UTooltip`) for any tooltip that needs more than a plain string. Built on `UPopover` in hover mode.
- **Label mode**: `<UiTooltip label="Stored on your PDS" title="Personal Data Server" description="..." />` renders the label text with a small info icon; hovering the icon shows the rich tooltip
- **Wrapper mode**: wrap any element in `<UiTooltip title="..." description="...">` to attach a tooltip to it
- **Sizes**: xs, sm, md (default), lg, xl control max-width
- **Style**: text-xs font-mono, bg-elevated border-default, pointer-events-none
- Use `UTooltip` only for simple single-line hints on icon buttons (e.g. "Copy to clipboard")

### Progressive Disclosure Components
- **Hover cards**: secondary metadata (version, updated date, source) appears on hover via tooltip or popover. Content is text-xs mono
- **Collapsible sections**: API changes, type signatures, compatibility matrices default to collapsed. Trigger is a text button with chevron icon
- **Expandable rows**: list items show one-line summary; click expands inline to show full detail without navigation
- **Detail panels**: slide-over or dedicated route for full metadata view. This is where data density peaks
- **Data labels**: top-level metrics are singular and labeled ("12 skills", "3 curators"); expanded views show the full breakdown

## Spatial & Motion

- **Spacing system**: Tailwind 4pt base: 4, 8, 12, 16, 24, 32, 48px
- **Spacing philosophy**: compact and defined. Sections separated by py-12 md:py-16 (not py-16 md:py-24). Cards at p-4. Breathing room is structural, never decorative
- **Vertical rhythm**: gap-3 to gap-4 between list items; gap-6 to gap-8 between sections within a page
- **Transition speed**: 200ms for all micro-interactions (hover, focus, expand/collapse)
- **Animation style**: fade-up with translateY(4px) (not 8px), stagger 60ms between siblings via motion-v; total under 400ms
- **Reduced motion**: opacity-only fallback for all spatial animations

## Responsive Strategy

- **Approach**: mobile-first, 3 breakpoints (sm/md/lg)
- **Container**: max-w-5xl (not 6xl) with px-4 sm:px-6
- **Input method**: hover effects only with @media (hover: hover); touch targets minimum 44px
- **Navigation**: mobile hamburger with slide drawer; desktop horizontal nav
- **Progressive disclosure on mobile**: hovers become tappable expand/collapse; no hover-only data

## Voice & Tone

> Full voice system, banned language, and messaging framework in `brand-guidelines.md`. Below are UI-specific copy patterns.

- **Button labels**: short verb phrases in mono: "Browse", "Install", "View skills". Never include "PDS" or "Personal Data Server" in button text. Use action + object: "Publish skills", "Update collection"
- **CTA patterns**: first action = "Publish [noun]", subsequent updates = "Update [noun]". Keep it about the action, not the storage destination
- **PDS terminology**: always use the abbreviation "PDS", never spell out "Personal Data Server" in UI copy. When PDS appears in explanatory text, pair it with a `UTooltip` or `<abbr>` so new users can learn the term. The tooltip text is: "Your Personal Data Server stores your data on the AT Protocol. You own and control it."
- **Storage attribution**: next to publish buttons, show "Stored on your PDS" as muted helper text with an info icon and tooltip. Do not put storage details in the button label itself
- **Error style**: direct, no fluff: "Couldn't load curators. Check your connection and try again."
- **Empty states**: acknowledge, explain value, provide action: "No collections yet. Curators bundle their favorite skills into collections you can install with one command."
- **Data labels**: always label metrics with context, never bare numbers. "12 skills" not "12". "Updated 3d ago" not "Mar 25"

## Avoid

- Glow effects, box-shadows on cards, backdrop-blur on surfaces
- Cold colors (blue, cyan, purple) as primary accents
- Pure black (#000) or pure gray (0 chroma) anywhere
- Leaderboard or ranking patterns; never sort by download count as primary view
- Dense data tables on first-level views; density increases with depth
- Emoji or playful illustrations
- Gradient text effects
- Nesting cards inside cards; use spacing and dividers
- rounded-xl on components (too soft; use rounded-lg)
- Large font sizes in UI chrome; reserve large type for page headings only
- Generous padding "for breathing room"; padding should be structural
- Showing all available data at once; layer it through progressive disclosure
- Spelling out "Personal Data Server" in UI copy; always use "PDS" with a tooltip
- Mentioning PDS or storage location in button labels; buttons describe the action, not the destination

## Custom Utilities

| Class/Token | What it does | When to use |
|-------------|-------------|-------------|
| `.section-label` | font-mono text-xs uppercase tracking-widest text-muted | Above each content section as a category label |
| `.surface-warm` | warm dark bg (oklch 0.16) with subtle warm border | Card or panel backgrounds in dark mode |
| `.surface-warm-elevated` | slightly lighter warm bg (oklch 0.20) with warm border | Elevated panels, dropdowns, popovers in dark mode |
| `.data-label` | font-mono text-xs text-muted tabular-nums | Inline metric labels in lists and cards |
